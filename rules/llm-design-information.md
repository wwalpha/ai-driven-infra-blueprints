# LLM Design Information Rules

- human-readable current designは`docs/designs/<environment>/<aws-account-id>/`に置く。
- machine-readable intended-design mirrorは`llm/designs/<environment>/<aws-account-id>/`に置く。
- machine-readable current actual valuesは`llm/actuals/<environment>/<aws-account-id>/`に置く。
- 旧 design 配下の LLM helper directory は obsolete であり、再作成を禁止する。
- Markdown design が human-readable current-design source of truth である。
- `llm/designs/`は`scripts/sync-design-mirror.py`が生成する同期mirrorであり、手動編集しない。
- Markdownとgenerated mirrorが一致しない場合はlocal loopを失敗させる。片方を黙って採用しない。
- design taskはMarkdownとJSON artifactを保存した後、同じcoherent logical changeでmirrorを生成する。
- Markdownの構造、service grouping、generated identifier rowは`rules/detailed-design.md`を正本とする。

## Format

UTF-8の`.properties` fileを使用する。file先頭、service ownership metadata、resource、design row、implementation noteはgeneratorが次の形式で出力する。

```properties
# Generated by scripts/sync-design-mirror.py; do not edit.
designService.vpc.serviceId=vpc
designService.vpc.ownedCatalogResourceTypes=EC2.VPC,EC2.Subnet
designResource.001.resourceType=EC2.VPC
designResource.001.logicalId=VPC01
designResource.001.anchor=vpc-vpc01
designRow.001-001.property=EC2.VPC.CidrBlock
designRow.001-001.value=10.1.0.0/16
designRow.001-001.comment=VPCで使用するIPv4アドレス範囲
designRow.001-002.artifactSha256=<linked-json-sha256>
designNote.001.text=実装注記: 必要最小限の注記
```

`designResource`と`designRow`の番号はMarkdown内の出現順から生成する。resource-detail tableのProperty、Value、Source / Commentはlosslessにmirrorへ反映する。policy JSON本文は複製せず、Markdownのrelative linkを`designRow.*.value`へ保持し、その内容のSHA-256を`designRow.*.artifactSha256`へ生成する。

generated current identifier rowはintended design mirrorへ出力しない。deploy前の`PENDING_DEPLOY`とdeploy後のphysical IDはMarkdownと`llm/actuals/**`の現行ルールに従い、generated mirrorへ複製しない。

生成command:

```console
python scripts/sync-design-mirror.py --write --environment <environment> --aws-account-id <aws-account-id>
```

## Grouping

- AWS service ownership boundaryごとにMarkdownとpropertiesを一対一対応させ、同じService ID、相対path、file stemを使う。
- `designService.<service-id>.serviceId`のkeyとvalueはfile stemと一致させる。
- `designService.<service-id>.ownedCatalogResourceTypes`はMarkdownと同じresource typeを同じ順序でcomma区切りにする。
- 別serviceのresource referenceはMarkdownのrelative linkとexplicit anchorをそのままmirrorへ保持する。
- 別serviceのdesign valueを参照元properties fileへ複製しない。
- `llm/designs/**`はintended design、service ownership、resource row、relative referenceだけを保持する。
- current physical valueとtarget/collection metadataは`llm/actuals/**`へ分離する。
- generated ARN を `llm/actuals/` に保存しない。
- AWS managed-policy ARN のような既存／human-provided design input は必要な場合に `llm/designs/` へ残してよい。
- referenceは同じenvironment/AWS account内のstable logical referenceをdefaultとする。cross-account referenceは所有AWS accountと接続方式をhuman designに明示し、値を推測しない。
