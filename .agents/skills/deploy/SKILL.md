Read `framework/prompts/codex/04_deploy.md` in full and execute its authoritative workflow and required rule readings. Treat invocation input as Human workflow input. Stop if the prompt is missing.

Every CloudFormation invocation uses current Worktree inputs and AWS state. DeployRunContext is memory-only. Never read or migrate old Deploy Sessions, Workflow ledgers/registries, repair histories or Human approval histories. Current destructive ChangeSets still require explicit Human consent and immediate ID/Stack/content/input revalidation. Only unfinished AWS/Secrets/Observed/publication operations use the minimal external Journal; confirmed completion removes its data. Settle scoped original AWS identities/tokens independently of an old Task digest, then verify the current Task's authority and exact Model/publication before/after. Linked worktrees must prove the same Git repository and target before local rebinding. Keep other scopes' unfinished evidence and prove both transitive dependency directions and publication isolation before unrelated Deploys. Deploy and Implement Handoff share one dependency proof: index ListExports by owner, overlay unfinished Delivery and current IaC imports, and query ListImports only for exports owned by reachable Producer-to-Consumer stacks starting at both scopes. A shared Producer alone is independent. Reuse reads only within that proof; incomplete or failed required reads block. Recovered success never constrains a new run to old IaC. Unknown submissions retain their original identity and never re-Execute with a new token.

Use the OS advisory lock on a stable private lock file; process exit releases it, file existence does not block, and unlock never unlinks it. Close contexts on every exit. Reclaim only signed, owned, unreferenced temporary inputs under that lock. Preserve templates referenced by unfinished operations, pending Observed/generation, repair requests and unconsumed signed failures; report uncertain cleanup. Failure issuance, repair-request creation, explicit discard and template reclamation share a repository OS lock outside request directories, acquired after the Journal lock. Task changes and new Deploys never expire unconsumed proofs. Verified repair integration discards its request and only an otherwise unreferenced failure. Explicit abandonment uses `deploy_handoff.py --failure <failure.json> --discard-failure`; unknown ownership/references block discard. Reclaim unreferenced owned templates at the next safe cleanup. Retention grants no old Task authority; current Task, target, signature and input checks still apply.

Preserve lazy Stack inputs, shared Load Once / same-generation Validate Once Model Cache, DeployOrder/concurrency, fresh AWS boundaries, per-success Observed sync and atomic publication. Deploy never edits IaC. A proved defect uses a separate authorized Implement Task with a one-shot pinned request, static validation and exact commit integration. Discard temporary evidence after delivery. Subsequent Deploy is independent; do not automatically chain unlimited new invocations. Terraform, Import, Destroy and Issue Gate retain their separate boundaries.

Model 更新時は **Change Validation のみ**実行する。Full Validation は Issue Scan や独立した明示的全量検証で使用し、更新の停止判定へ混入させない。変更した Resource / Property / Link と、それらが使用・破壊する参照契約を検証し、無関係な既存エラーを更新の停止理由にしない。読み取り依存先、検証対象、生成対象、Task の書き込み権限を区別する。
